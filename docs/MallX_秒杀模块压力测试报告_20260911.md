# MallX 秒杀模块压力测试报告

测试时间：2026-09-11  
测试环境：Windows 11，本机同时运行JMeter、MallX、MySQL、Redis、RabbitMQ和Elasticsearch  
测试对象：Redis Lua资格预扣、RabbitMQ异步削峰、异步订单消费及最终一致性

## 1. 验收结论

本轮秒杀专项验收通过。500个独立用户同时争抢100件库存时，准确产生100个成功资格和400个售罄业务拒绝，系统错误率为0%；没有超卖、重复请求记录或重复用户订单。正常消费和受控积压两种模式均能最终收敛为100个订单，RabbitMQ业务队列和死信队列最终均为0。

“售罄”是库存边界内的正常业务结果，不属于系统错误；本报告中的0错误指HTTP 5xx、非预期业务异常、MQ异常、消费失败和数据不一致均为0。

## 4. 受控异步削峰测试

本轮仅通过运行参数暂停RabbitMQ消费者，保留Redis资格预扣和MQ生产者。500个请求结束后先检查中间状态，再重启正常消费者。

### 消费者关闭时

| 指标 | 结果 |
| --- | ---: |
| 抢购请求 | 500 |
| 资格预扣成功 | 100 |
| 售罄预期拒绝 | 400 |
| 系统错误 | 0 |
| 抢购突发窗口 | 629 ms |
| 突发吞吐量 | 794.91 请求/秒 |
| 平均响应时间 | 436.38 ms |
| P95 | 605 ms |
| P99 | 618 ms |
| 最大响应时间 | 622 ms |
| RabbitMQ Ready消息 | 100 |
| RabbitMQ消费者 | 0 |
| MySQL秒杀订单 | 0 |

这组中间状态证明抢购入口不等待订单落库：请求先由Lua完成原子资格判定，再由RabbitMQ保存100个成功请求，数据库写入压力被转移到后续消费者。

### 恢复消费者后

| 检查项 | 结果 |
| --- | ---: |
| 成功请求记录 | 100 |
| 正式订单 | 100 |
| 秒杀商品sold_stock | 100 |
| RabbitMQ Ready/Unacked | 0/0 |
| RabbitMQ死信消息 | 0 |
| JVM启动至全部收敛 | 21.945 s |
| 100条成功请求落库时间跨度 | 2 s |

`21.945 s`包含Spring Boot启动时间，不能解释为纯消费耗时；数据库中100条请求的创建时间跨度为2秒。

## 8. 说明

本结果是同机开发环境基线，适合验证实现正确性和比较后续代码改动，不代表生产环境容量。生产容量评估应将压测机、应用、MySQL、Redis和RabbitMQ分离部署，并补充长稳压测、消费者故障恢复和资源监控。
